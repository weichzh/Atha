# 项目工作流技能

## 启动

1. 读取 `AGENTS.md`；
2. 读取 `docs/ACTIVE.md`；
3. 确认当前模式；
4. 只加载 `ACTIVE` 指定的上下文；
5. 上下文不足时再读 `docs/INDEX.md`；
6. `ACTIVE` 过期或矛盾时，先修复文档再写代码。

## 模式

### discussion

允许：提问、比较方案、记录讨论、提出决策或规格。禁止修改生产代码。

### specification

允许：起草或修订规格、验收标准和自审。禁止修改生产代码。

### planning

允许：编写实施计划、列出文件、测试和回滚，并请求交叉审阅。禁止修改生产代码。

### implementation

只有同时满足以下条件才允许进入：

- active 里程碑存在；
- 规格状态为 `accepted`；
- 计划状态为 `accepted`；
- 交叉审阅已批准或只有非阻塞建议；
- `ACTIVE` 允许生产代码修改；
- 用户明确批准实施。

实施后必须运行检查、更新 `ACTIVE` 和相关代码库文档、写评审记录，并运行两个文档守卫脚本。

### review

允许：检查 diff、运行检查、记录发现、更新评审和 `ACTIVE`。禁止计划外生产修改。

## 失败行为

请求违反门禁时停止，并明确缺少的前置条件。优先补齐文档，不绕过工作流。

## 最小上下文

不得默认加载整个 `docs/`。顺序固定为 `ACTIVE` → 必要时 `INDEX` → 当前任务明确引用的文档。
