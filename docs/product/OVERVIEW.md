# Atha 产品定义

## 一句话

Atha 是一个本地优先的电子书阅读器：把围绕原文的笔记组织成即时通讯线程，让读者不是只给书做批注，而是在与一本书对话。

## 要解决的问题

许多电子书阅读器为了跨平台或简化实现，使用自制 parser 或有限的 UI 重建书籍页面。复杂 CSS、字体、数学公式、SVG 和长章节容易显示不完整或变慢。书源有样式问题时，用户通常只能等待阅读器逐本修复。

Atha 的目标是让阅读器的内容还原以浏览器为基准，同时让用户能够像浏览器用户样式工具一样，为特定书籍应用和分享 CSS 修复。

多数阅读器仍把笔记设计成批注表单或文档列表，难以承载吐槽、赞叹、追问和反复商榷。Atha 让一段原文成为对话起点，并以稳定的列表、线程和回复关系保留读者的思考过程。当前对话中的消息都来自用户；AI 角色实装前，界面不伪造作者身份或作者回复。

许多阅读器直接打开 Kindle 词典的超长目录，导致导入或首次使用迟缓。Atha 在本地建立受控索引，再提供与阅读选区相连的精确查词；这是格式适配与性能边界，不是附加的在线词典服务。

## 主循环

> 打开书籍内容 → 阅读与选择原文 → 在阅读页内发出引用消息 → 围绕引用继续讨论、搜索与回顾。

阅读是入口；引用消息是思考与交流的最小记录单位；书内位置和当时的渲染快照共同保证引用长期可回看。

## 核心体验

### 高保真阅读

- 阅读内核以 HTML、CSS 和本地资源的正确呈现为首要目标；格式导入只是把不同书籍来源送入同一个内容模型的入口。
- 复杂内容的正确性以浏览器呈现为对照；书内脚本默认不执行，外部网络资源默认拦截并由用户按需确认。
- 默认阅读样式借鉴成熟阅读产品中已验证的部分：单栏正文保持稳定行长，视觉页边距不随 DPR 偶然变化，宽屏也先进入无常驻工具的专注阅读；不为少数需求堆叠设置，深度定制交给 CSS。
- 应用外观、全书阅读默认和本书覆盖属于不同作用域；书架设置不冒充阅读界面，阅读中的常用调节也不被搬离当前上下文。
- 同一操作随输入方式使用原生惯例：触控长按与双指、桌面右键与滚轮共享同一书籍和内容状态，不复制功能。
- 书源内容无法可靠渲染时明确报错，不静默猜测、降级或替用户修复书源。

### 性能优先级

- 长章节、数学公式和 SVG 等重内容仍应保持可读和顺畅。
- 重内容先保留稳定布局，再逐步完成计算；当前视口优先，视口外可延后。
- 首次打开允许建立缓存或预处理，以换取之后阅读和再次打开的速度。
- 用户可为特别重的内容选择性能优先模式，接受部分样式效果的取舍。

### 消息式共读

- 选中原文后可写下吐槽、赞叹或疑问；该消息成为围绕这段原文继续回复的线程，而不是孤立批注。
- 竖屏把笔记列表与当前线程作为同一悬浮笔记窗口的前后两页；横屏从左到右按任务显示正文与列表、列表与线程，或正文、列表、线程三栏。
- 用户界面以“笔记”为功能入口，以“标注”指只高亮原文的记录，以“对话”指围绕原文展开的线程，以“消息”指线程中的单条正文或回复；范围只显示“当前 / 本章 / 本书”。
- 消息可以引用书籍原文或其他消息，因此对话线程、章节位置和关联网络是同一份数据的不同视图。
- 引用除了导航位置，还保存当时的 HTML、CSS 及所需资源快照；书源或样式变化后，历史对话仍可如实呈现。

### AI 书友

AI 书友是长期方向，而不是当前实现范围。它们可拥有不同角色，并在用户授予的渐进式 skills 范围内自行决定是否检索书内内容、上下文或其他资料。此能力必须建立在稳定的书内引用、消息和搜索模型之上。

## 产品边界

- 当前优先 Windows，后端和领域模型不得依赖某个前端框架。
- 书内脚本不执行；外部资源默认不加载，用户确认后才可加载。
- 云同步、账户、移动端、应用内 CSS 社区和 AI 平台化均不是当前交付前提。
- 备份、迁移和格式扩展从已建立的数据模型推导，不预先发明独立方案。

## 验收原则

维护一组困难书籍样本：每本覆盖明确的渲染或性能难点。实现变更应以同一批样本对照浏览器效果，并衡量打开、排版和阅读过程中的性能。样本由产品方维护，具体检查在后续规格中定义。
