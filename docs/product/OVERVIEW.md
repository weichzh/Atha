# Atha 产品定义

## 一句话

Atha 是一个本地优先的电子书阅读器：把围绕原文的笔记组织成即时通讯线程，让读者不是只给书做批注，而是在与一本书对话。

## 要解决的问题

许多电子书阅读器为了跨平台或简化实现，使用自制 parser 或有限的 UI 重建书籍页面。复杂 CSS、字体、数学公式、SVG 和长章节容易显示不完整或变慢。书源有样式问题时，用户通常只能等待阅读器逐本修复。

Atha 的目标是让阅读器的内容还原以浏览器为基准，同时让用户能够像浏览器用户样式工具一样，为特定书籍应用和分享 CSS 修复。

多数阅读器仍把笔记设计成批注表单或文档列表，难以承载吐槽、赞叹、追问和反复商榷。Atha 让一段原文成为对话起点，并以稳定的列表、线程和回复关系保留读者的思考过程。当前对话中的消息都来自用户；AI 角色实装前，界面不伪造作者身份或作者回复。

许多阅读器直接打开 Kindle 词典的超长目录，导致导入或首次使用迟缓。Atha 在本地建立受控索引，再提供与阅读选区相连的精确查词；这是格式适配与性能边界，不是附加的在线词典服务。

## 主循环

> 打开书籍内容 → 阅读与选择原文 → 在阅读页内发出引用消息 → 围绕引用继续讨论、搜索与回顾。

阅读是入口；引用消息是思考与交流的最小记录单位；书内位置和当时的渲染快照共同保证引用长期可回看。

## 核心体验

### 高保真阅读

- 阅读内核以 HTML、CSS 和本地资源的正确呈现为首要目标；格式导入只是把不同书籍来源送入同一个内容模型的入口。
- 复杂内容的正确性以浏览器呈现为对照；书内脚本默认不执行，外部网络资源默认拦截并由用户按需确认。
- 默认阅读样式借鉴成熟阅读产品中已验证的部分：单栏正文保持稳定行长，视觉页边距不随 DPR 偶然变化，宽屏也先进入无常驻工具的专注阅读；不为少数需求堆叠设置，深度定制交给 CSS。
- 应用外观、全书阅读默认和本书覆盖属于不同作用域；书架设置不冒充阅读界面，阅读中的常用调节也不被搬离当前上下文。
- 同一操作随输入方式使用原生惯例：触控长按与双指、桌面右键与滚轮共享同一书籍和内容状态，不复制功能。
- 书源内容无法可靠渲染时明确报错，不静默猜测、降级或替用户修复书源。

### 性能优先级

- 长章节、数学公式和 SVG 等重内容仍应保持可读和顺畅。
- 重内容先保留稳定布局，再逐步完成计算；当前视口优先，视口外可延后。
- 首次打开允许建立缓存或预处理，以换取之后阅读和再次打开的速度。
- 用户可为特别重的内容选择性能优先模式，接受部分样式效果的取舍。

### 消息式共读

- 选中原文后可写下吐槽、赞叹或疑问；该消息成为围绕这段原文继续回复的线程，而不是孤立批注。
- 竖屏把笔记列表与当前线程作为同一悬浮笔记窗口的前后两页；横屏从左到右按任务显示正文与列表、列表与线程，或正文、列表、线程三栏。
- 用户界面以“笔记”为功能入口，以“标注”指只高亮原文的记录，以“对话”指围绕原文展开的线程，以“消息”指线程中的单条正文或回复；范围只显示“当前 / 本章 / 本书”。
- 消息可以引用书籍原文或其他消息，因此对话线程、章节位置和关联网络是同一份数据的不同视图。
- 引用除了导航位置，还保存当时的 HTML、CSS 及所需资源快照；书源或样式变化后，历史对话仍可如实呈现。

### AI 书友

AI 书友是长期方向，而不是当前实现范围。它们可拥有不同角色，并在用户授予的渐进式 skills 范围内自行决定是否检索书内内容、上下文或其他资料。此能力必须建立在稳定的书内引用、消息和搜索模型之上。

## UI / UX 决策基线

### 如何阅读本节

本节不把所有设计句子写成同一种“正确”。每项主张先标明来源和状态；产品选择、规范门槛、当前合同与实验观察不能互相冒充。

| 标记 | 主张类型 | 它能决定什么 | 它不能证明什么 |
| --- | --- | --- | --- |
| `P` | 产品公理 | Atha 选择服务谁、解决什么问题，以及不能被优化掉的产品身份 | 市场中的所有用户都会喜欢 |
| `G` | 硬门 | 候选是否因语义、数据、安全或基本操作错误而应被淘汰 | 界面已经美观或高效 |
| `C` | 已批准体验合同 | 后续实现必须保持的任务关系、状态与作用域 | 该合同是所有产品的普遍最优解 |
| `E` | 有范围的证据结论 | 某一夹具、视口、平台和方法实际观察到什么 | 未执行的平台、任务或长期体验也有相同结果 |
| `H` | 未决假设 | 下一次原型或任务测试需要比较什么 | 当前已经可以作为实现定论 |

本节列出的 `P` 与 `C` 均为当前已批准的产品选择。后续新增条目按类型留下最小收据：`P` 写明产品所有者和替换条件；`G` 写明适用范围、判定条件和可执行检查；`C` 写明状态、顺序、不变量和复查触发器；`E/H` 写明方法、证据、反证或失效条件，以及 `通过 / 失败 / 担忧 / 未知 / 不适用 / 未执行` 中的一种状态。缺少对应收据的设计意见只能作为候选，不进入稳定合同。

### `P` 产品公理

- `P1` 阅读是入口；一段原文是对话起点。笔记不是脱离书籍的记录管理器，而是围绕原文继续吐槽、赞叹、追问和商榷的消息线程。
- `P2` 默认界面应当完整、克制且有主见。Atha 服务不关心小众选项的普通读者，也服务愿意使用 Web 知识和 CSS 模块深度定制的专家；它不把专家能力改造成持续增长的专用开关集合。这是产品取舍，不是用户研究结论。
- `P3` 当前消息都来自用户；AI 书友不是产品成立前提。界面不得为了“像聊天”而伪造作者、AI 或其他发送者。
- 微信读书式安静阅读、Readest 的工具组织和 Telegram 的消息结构只用于校准成熟表达。它们证明某种方案存在，不拥有 Atha 的价值决定权。

### `G` 不可补偿的硬门

- `G0` 语义诚实与数据安全：不伪造身份；危险操作可以预防或恢复；引用回到真实原文和历史快照。任一失败即淘汰，不能由美观、功能或其它视口抵消。
- `G1` 基本可访问与可操作：满足目标平台适用的 WCAG 2.2 AA；键盘焦点可见且不被遮挡；紧凑窗口没有让任务不可达的双轴滚动。主要触控动作以 `44 × 44 CSS px` 为 Atha 的质量目标，不把它误称为 WCAG 2.2 AA 的统一阈值；只有 change 把某个动作明确登记为主要触控动作时，小于该目标才单独构成当前任务的 `G1` 失败，任务不涉及触控时标为“不适用”。
- `G0/G1` 必须由相应状态下的可执行任务检查。截图不能证明删除取消、焦点、键盘、触控目标、保存、返回或状态可达性；未执行时只能写“未知”或“未执行”。

### `C` 已批准体验合同

`C1` 定义三个稳定任务区域：`A` 是正文，`B` 是笔记 / 对话列表，`C` 是当前消息线程。正文文本列在自己的书页区域内居中，但正文栏本身不得放到 `B` 与 `C` 之间；允许的横屏顺序只有 `A | B`、`B | C` 和 `A | B | C`，明确禁止 `B | A | C`。

| 情境 | 当前投影合同 |
| --- | --- |
| 专注阅读 | 只显示 `A` |
| 横屏宽视口的列表 | `A | B` |
| 横屏宽视口打开线程 | `A | B | C`；专注对话时切为 `B | C` 并隐藏 `A` |
| 横屏中等视口 | 在 `A | B` 与 `B | C` 之间切换 |
| 竖屏或窄视口 | `A` 保持为底层阅读页；同一悬浮笔记窗口分别显示 `B`、`C` 两页，以 `B → C → B` 切换并保留列表位置；关闭窗口回到 `A`，并可从正文重新打开 |

当前实现和消融夹具使用 `800px`、`1440px` 作为中等与宽视口参考值。它们是可调整的实现阈值，不是已经证明最优的产品公理；无论阈值如何变化，上表中的顺序、返回关系和状态可达性必须保持。

`C2` 固定设置作用域，而不固定设置入口的位置：

- 应用外观只影响资料库、阅读记忆和应用设置；
- 全书阅读默认影响没有本书覆盖的阅读体验；
- 本书覆盖只影响当前书；
- CSS 模块属于需要明确进入的专家能力，并继续受安全边界限制。

界面必须让用户在操作前判断影响范围，并在操作后看到对应上下文中的反馈。右上浮层、底部抽屉或独立页面只是候选承载方式，不能用入口存在替代作用域清楚。

`C3` 固定消息语义，而不固定消息外形：`B` 是围绕原文的对话索引；`C` 先呈现可跳回的原文，再呈现我的回应以及真实回复 / 引用关系。时间线、气泡或混合布局都必须同时让关系可核对，并让产品仍被识别为“与一本书对话”。

### `E` 当前证据结论

当前最高证据只到 Linux 本地 Vite / Chromium 固定视口截图、运行时几何、确定性交互探针和两份盲评记录。详细证据位于 `docs/changes/ui-constraint-ablation.md` 和本机 `artifacts/local/experiments/ui-ablation-20260904/report.md`。

- `E1`：控制组 `C0` 的删除取消、焦点回归、`B → C → B`、关闭和重开通过本地探针；`A1` 取消仍删除，触发本地 `G0`；`A2` 焦点不可见，触发本地 `G1`。静态截图无法区分这些行为。
- `E2`：两名盲评者都识别出 `A3` 的顺序、面积、空白、堆叠或截断问题。这是当前夹具与固定视口下的高置信静态担忧；`C1` 的约束力来自产品批准，实验只验证实现是否偏离它，不证明它是普遍定律。
- `E3`：`A4` 在 `360 × 760` 使 `B/C` 位于视口外且没有可用到达路径，触发本地 `G1`。这不等于所有移动平台已经验收。
- `E4`：`A5` 的四行设置入口都只显示“设置”且没有作用域副文案，两名盲评者都发现范围不可区分。本轮没有执行真实设置写入，也没有证明右上角锚定本身错误。

### `H` 未决设计假设

| 假设 | 当前状态 | 需要什么证据才能决定 |
| --- | --- | --- |
| `H1` 设置应位于右上浮层、底部抽屉还是独立页面 | 未定 | 在具体平台上比较发现、范围预测、即时反馈、恢复和遮挡 |
| `H2` 哪些控件应常驻，哪些应渐进披露 | 未定 | 测量真实任务频率、发现时间、误触、阅读中断和长期使用 |
| `H3` 线程应采用气泡、时间线还是混合语法 | 未定 | 同时测试关系核对和“与书对话”的第一印象，不能只优化其中一项 |
| `H4` `800px`、`1440px` 及各栏宽度是否合适 | 未定 | 在目标平台、真实长书、长消息和大量笔记下验证可达性、行长、密度与疲劳 |

常驻控件没有遮挡正文，不足以证明它更好或更差；时间线让盲评者更容易核对关系，也不足以证明它更符合 Atha。留白、圆角、密度和控件数量都不得脱离任务指标被写成审美定律。

### 判定与证据规则

1. 先声明当前任务、目标平台、视口 / 状态和适用的 `P`；不采用某项产品公理时必须明说，而不是暗中换评价函数。
2. 先执行适用的 `G`。失败即淘汰；未执行保持未知，不进入审美比较。
3. 再检查候选是否满足 `C`，并用同一内容、状态和视口比较构图、长文可读性、符合预期、披露、效率、密度、一致性与产品性格。
4. 本轮消融曾把上述维度登记为 `V1-V9` 并按词典序判断，但没有与其它排序做对照，因此该顺序只解释本轮实验，不是已经验证的永久价值排序。以后复用这些维度时，必须按具体任务预先声明优先关系和推翻条件。
5. 竞品截图只证明可见实现；静态截图只证明画面；本地交互只证明当前夹具；真实平台和长期用户价值需要各自证据。分歧或证据不足时，结论必须保持“未定”。

## 产品边界

- 当前优先 Windows，后端和领域模型不得依赖某个前端框架。
- 书内脚本不执行；外部资源默认不加载，用户确认后才可加载。
- 云同步、账户、移动端、应用内 CSS 社区和 AI 平台化均不是当前交付前提。
- 备份、迁移和格式扩展从已建立的数据模型推导，不预先发明独立方案。

## 验收原则

维护一组困难书籍样本：每本覆盖明确的渲染或性能难点。实现变更应以同一批样本对照浏览器效果，并衡量打开、排版和阅读过程中的性能。样本由产品方维护，具体检查在后续规格中定义。
