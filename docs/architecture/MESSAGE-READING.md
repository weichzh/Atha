# 消息式阅读与共读

## 目的

阅读中的摘录、吐槽、解释和讨论本来常被转发到聊天工具。Atha 将这段交流留在书内：消息引用原文或另一条消息，阅读位置、聊天记录和关联网络因此保持可互相跳转。

## 交互边界

- 阅读页始终是主界面。
- 创建引用后，显示可拖动调高或全屏的对话浮层，不跳转到完整聊天页。
- 浮层保留当前引用的短预览；发送、保存或关闭后，点击正文即可继续阅读。
- 完整对话、按章节回看和关联视图是同一消息数据的不同呈现，不各自维护副本。
- 对话浮层的本条、本章和本书只是同一 Message 查询的范围参数；聚合范围可以按消息创建时间或根 Message 的书内 Locator 排序，写入仍只发生在单个 Conversation 中。

## 引用存档

每个原文引用同时有两个职责：

1. 导航：记录书内位置，便于跳回相关上下文；
2. 存档：记录选中内容的 HTML、当时生效的 CSS 以及呈现所需的资源版本。

存档是历史消息展示的权威来源。原书重导、原文改动或用户样式变更后，旧消息仍展示当时的引用；导航位置仅用于回到当前书籍上下文。

`SourceAnchor` 与 `SourceSnapshot` 是不同事实。Anchor 保存不可变的原始 Locator、原文、上下文和内容哈希，并可另存经过唯一重锚后的当前 Locator；Snapshot 保存已校验的选区 HTML、创建时实际启用的 reader/book/user CSS、呈现参数和选区所需本地资源。自动重锚不能改写 Snapshot；用户主动重选原文则生成新的 Anchor 与 Snapshot 版本。

## 消息事实

- `Conversation` 属于一个具体 Edition，并由引用原文的根 Message 开始；
- `Message` 是唯一稳定用户事实；只含原文引用时投影为标注，含用户正文时投影为笔记或对话消息，不再维护独立 Annotation 事实；
- 每个 Message 都有不可变 `MessageRevision`：source-only 修订表示纯标注，text 修订保存笔记或回复；文字修订可携带经过 allowlist 校验的 Tiptap JSON，`plain_text` 是由同一正文得到的搜索与兼容投影；添加笔记和编辑只追加修订并切换当前修订；
- 根 Message 拥有 `SourceAnchor` 与 `SourceSnapshot`；主动重选原文会创建新的 Anchor 与 Snapshot 版本并保留旧版本，自动唯一重锚只更新当前导航 Locator；
- 回复至多指向一个父消息；一条消息可以另外引用多条既有消息；关系必须同时支持正向和反向查询；
- 删除是墓碑，不物理删除修订、引用、关系或历史快照；默认阅读视图不显示已删除正文；
- 高亮覆盖、笔记列表、对话浮层、章节回顾和关系视图都是同一 Message 事实的投影，不各自维护耐久副本。

SQLite 与本地内容寻址资产是消息事实源。产品界面只通过应用服务操作消息；阅读页提供选区捕获和 Locator 跳转，不直接读写数据库。

## 当前实现

- `backend::messages::MessageStore` 隐藏 schema v2 迁移、WAL、外键、FTS5、事务 Outbox、快照资产恢复、旧标注迁移、自包含交换导出及完整备份 / 恢复；资源在 SQLite writer lock 内通过同目录临时文件、`sync_all` 和 rename 发布，重开会清理 Atha 临时文件与数据库未引用的规范哈希资产；`Assets` 根必须是实际目录，读取、导出、备份与复用统一拒绝 symlink 等非普通资产；
- 阅读内核从已验证 Range 捕获一份候选 Anchor、选区 HTML、生效 CSS、呈现参数和实际引用资源，Tauri command 在写入前再次执行信任边界校验；
- 首次打开会把旧 localStorage 标注原子、幂等地导入 Message Store；成功后阅读页只从正式根 Message 投影高亮和笔记，不继续双写；
- 全屏笔记页支持全文与章节筛选、进入对话和导出本书消息；新增或编辑笔记直接打开定位到根消息的半屏底部对话浮层，浮层可拖动调高或进入全屏，并支持回复、编辑、删除、修订、关系回顾、历史快照和跳回；
- 消息输入器由 Tiptap 承担编辑状态和 JSON 序列化，随换行增高；超过紧凑高度后可展开为全屏编辑器。全屏工具栏分为输入模式与文字格式两层，用户可在可视化编辑和原始 Markdown 之间无损切换；Markdown 只作为临时输入视图，持久化仍是同一份受限 JSON。当前正文 schema 只接收段落、三级以内标题、列表、引用、换行及粗体、斜体和安全链接，不接收任意 HTML；
- 历史快照在隔离的 Shadow Root 中以 `.book` 容器、存档 CSS、冻结的主题/字号/字体/行距/亮度和内容寻址资源呈现；外部 URL、CSS 子资源、活动内容、事件属性和未登记资源在后端与显示端均拒绝，不在显示时静默修复。

## 交换与完整恢复

- 按 Edition 或单 Conversation 导出的 `.zip` 是自包含交换制品，只覆盖所选业务范围，不包含完整数据库状态，也没有恢复语义；
- `.atha-backup` 是 schema 1 的完整 MessageStore 恢复制品，只包含 Online Backup API 生成的一致 `Messages.sqlite3`、严格 manifest 和该快照引用的全部且仅有内容寻址资产；
- 恢复是全量替换，不做 merge。backend 在正式写入前校验 entry 集合与容量、哈希、当前 database schema 精确签名、SQLite / 外键完整性、消息关系、Edition / 修订 / Locator / Snapshot 内容、Outbox、旧迁移凭据、FTS NULL-safe 精确投影和资产引用集合；未完成的数据库 copy 由 SQLite 回滚；
- 资料库页只负责选择文件、显示忙碌 / 取消 / 错误状态并确认替换全部消息事实；Tauri `message_maintenance` 只接受主窗口资料库根路由，制品与事务规则不进入前端。

## 关联语义

消息可引用原文，也可引用其他消息。关联信息必须支持查询“引用了什么”和“被什么引用”，从而形成可按会话、书籍、章节或关系链查看的阅读记忆。

## AI 书友的长期位置

未来可在书籍或群组中配置不同角色的 AI 书友，例如解释、考据或陪伴式吐槽。角色不是只有不同提示词：它们将在被授予的 skills 范围内决定是否检索当前书、相邻上下文或其他资料。

这只是长期方向。当前数据模型应避免排除消息作者、回复关系、引用关系和将来异步事件，但不实现 AI 调用、群组同步或权限系统。

## 非目标

- 不将完整即时通讯系统或真实多人同步纳入当前范围；
- 不为 AI 预先定义固定技能清单、工具协议或权限 UI；
- 不把消息记录做成脱离书籍语境的通用聊天产品。
- 当前不提供附件、图片、表格、公式、AI 写作或网络发送；这些能力需分别解决本地资源生命周期、导出和不可信内容边界后再进入正文 schema。
- 完整消息备份不包含 EPUB、书架、阅读进度或偏好，也不提供加密、云端、计划任务、增量或合并恢复。
