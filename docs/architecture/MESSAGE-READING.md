# 消息式阅读与共读

## 目的

阅读中的摘录、吐槽、解释和讨论本来常被转发到聊天工具。Atha 将这段交流留在书内：消息引用原文或另一条消息，阅读位置、聊天记录和关联网络因此保持可互相跳转。

## 交互边界

- 阅读页始终是主界面。
- 创建引用后，显示可收起、可调整大小的对话浮层，不跳转到完整聊天页。
- 浮层保留当前引用的短预览；发送、保存或关闭后，点击正文即可继续阅读。
- 完整对话、按章节回看和关联视图是同一消息数据的不同呈现，不各自维护副本。

## 引用存档

每个原文引用同时有两个职责：

1. 导航：记录书内位置，便于跳回相关上下文；
2. 存档：记录选中内容的 HTML、当时生效的 CSS 以及呈现所需的资源版本。

存档是历史消息展示的权威来源。原书重导、原文改动或用户样式变更后，旧消息仍展示当时的引用；导航位置仅用于回到当前书籍上下文。

## 关联语义

消息可引用原文，也可引用其他消息。关联信息必须支持查询“引用了什么”和“被什么引用”，从而形成可按会话、书籍、章节或关系链查看的阅读记忆。

## AI 书友的长期位置

未来可在书籍或群组中配置不同角色的 AI 书友，例如解释、考据或陪伴式吐槽。角色不是只有不同提示词：它们将在被授予的 skills 范围内决定是否检索当前书、相邻上下文或其他资料。

这只是长期方向。当前数据模型应避免排除消息作者、回复关系、引用关系和将来异步事件，但不实现 AI 调用、群组同步或权限系统。

## 非目标

- 不将完整即时通讯系统或真实多人同步纳入当前范围；
- 不为 AI 预先定义固定技能清单、工具协议或权限 UI；
- 不把消息记录做成脱离书籍语境的通用聊天产品。
