# Atha 架构总览

## 当前方向

Atha 是一个本地优先、以消息形式保存阅读反应的个人阅读系统。当前只面向 Windows 开发，并按“后端先于前端”的顺序推进；iOS、HarmonyOS 与其他移动平台已暂缓，不得创建相关工程或适配代码。

Windows 前端将在后端边界稳定后启动。窗口可以采用移动端式的窄布局和信息密度，但该设计选择不得反向污染领域模型与存储语义。

权威范围决策见 `docs/decisions/ADR-0001-windows-backend-first.md`。

## 产品主循环

> 导入书籍 → 阅读 → 选择原文 → 形成引用消息 → 写下反应 → 搜索与回顾。

阅读器是内容入口，消息是最小记录单位，原文定位是消息可信度的基础。AI、同步和移动端均不是当前产品成立的前提。

## 当前交付范围

当前阶段只建立可由未来 Windows 前端调用的后端能力：

- 稳定的项目和构建入口；
- `Work`、`Edition`、`Conversation`、`Message`、`MessageRevision` 与 `SourceAnchor` 领域语义；
- 固定版本 SQLite、WAL、FTS5 与 Outbox；
- 书籍上下文创建、引用笔记原子写入和当前修订搜索；
- 不记录正文、笔记和查询词的诊断边界；
- 可重复的格式化、测试和本地基准入口。

当前不实现：

- Windows 前端、阅读渲染器与文件选择器；
- iOS、HarmonyOS 或跨平台 UI；
- MOBI、AZW、PDF、OCR；
- 云同步、账户、AI 书友；
- 生产安装包与发布流程。

## 质量优先级

1. 数据正确性与可恢复性；
2. 隐私和内容不泄露；
3. 可测量的性能确定性；
4. 格式兼容性；
5. 代码复用率；
6. 功能数量。

静态、本地、真实目标与生产等价证据必须明确区分。Windows 本地跑通不能称为真实设备或生产验收。

## 分层边界

### Windows 产品界面层（暂缓）

负责窗口、导航、书架、阅读、消息和设置。只通过后端公开接口访问领域行为，不直接拼接 SQL，也不拥有事实数据。

### 应用服务层

负责用例边界、输入验证、事务和错误语义。首个纵向用例为“创建书籍上下文 → 保存引用笔记 → 写入 Outbox → FTS 检索当前修订”。

### 可移植核心层

负责领域模型、规范 Locator、富文本版本、内容哈希、统计规则和将来可能暴露的稳定 C ABI。核心不得依赖 Windows UI 类型。

### 数据层

SQLite 与本地资产是事实源。用户可变数据、全文索引和未来词典索引应保持可独立迁移和恢复。

### 平台适配层

未来负责 Windows 文件选择、安全存储、系统分享、生命周期和诊断导出。平台对象不得穿透应用服务边界。

## 核心数据语义

- `Work` 表示抽象作品；`Edition` 表示具体导入文件。
- `Conversation` 是某个版本的阅读对话容器。
- `Message` 保存稳定身份、作者、类型、回复关系和删除状态。
- `MessageRevision` 保存不可变编辑历史；搜索只返回当前修订。
- `SourceAnchor` 同时保存规范 Locator、后端快速定位数据、选中文本上下文和内容哈希。
- `OutboxEvent` 必须与事实写入处于同一事务；不得出现事实已提交而事件丢失。

## 安全与隐私边界

- 导入文件一律视为不可信输入。
- 禁止日志记录书名、原始路径、原文、笔记、查询词和 AI 提示词。
- JSON、ID、文件指纹和 Locator 在进入数据库前必须验证。
- 数据迁移、删除和导入失败必须有明确恢复路径。
