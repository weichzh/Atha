# 路线图

路线图只定义交付顺序，不授权生产代码修改。当前只推进下一个未完成的可实施切片；每个切片在同一份 `accepted` change 中记录问题、范围、验收、步骤、结果和 review，经用户批准后实施。不得为后续阶段预建 interface、adapter、数据库 schema 或占位目录。

## M0：项目工作流初始化（已完成）

项目记忆、文档所有权、检查入口与任务路由已经建立。历史过程由 Git 保存，不再作为当前实施主线。

## M1：Windows 后端工程初始化（已完成）

根 Cargo workspace、正式后端 crate、Rust 检查入口和 P0 隔离边界已经建立。后续公开 interface、错误模型和依赖继续由真实用例驱动。

## M2：阅读器 V1（已完成）

目标：先完成一个结构清楚、可持续扩展的 WebView2 阅读器，再考虑书架、消息、TTS、同步或其他产品能力。HTML、CSS、本地资源、安全边界、自适应视口内的绝对设备像素排版和困难样本验收继续遵循 `docs/architecture/READER-CORE.md`。

### 实施原则

- 严格按 R0 至 R8 顺序推进；一个阶段达到退出条件前不开始下一阶段；
- 一个阶段可以拆成多个纵向 change，但同一时间只推进一个；每个 change 只增加一种长期能力，同时整理被它真实触及的 module，不做顺手重构；
- 入口只负责组合和启动；实现规则进入拥有该职责的 deep module，并通过其小 interface 验证；
- 一个 adapter 只是设想中的 seam。只有第二种真实实现出现，或平台/信任边界必须隔离时才建立 adapter；
- 不用硬行数上限机械拆文件。入口开始实现业务规则，或一个功能需要同时修改三个不相干区域时，先拆清职责；
- 安全、错误处理、键盘与读屏基础、三份困难样本和相称 benchmark 是每个切片的持续 gate，不留到最后补做；
- 只优化真实测出的瓶颈，不提前建设持久缓存、worker、虚拟化框架或第二渲染引擎。

### Readest 参考方式

Readest 是阅读器能力、真实调用链和既有问题的学习对象，不是设计或技术栈模板。实施每个切片前，可以检查 `.tmp/readest-source` 中对应源码；当前可复现快照、已确认 seam 和限制记录在 `docs/research/readest-reader-capability-map.md`。

参考时依次回答：

1. Readest 从入口到耐久状态的真实流程是什么；
2. 哪些 module、interface 和状态生命周期值得学习；
3. 它是否已经出现巨型编排器、全局状态、重复写入或平台耦合等问题；
4. Atha 的 WebView2、安全、绝对页面几何和 reader-only 范围是否允许采用同一做法；
5. 能否用当前代码、浏览器能力或更小实现达到目标。

只有回答完这些问题，才把适用做法写入当前 change。不得复制 Readest 的视觉、交互设计、Next.js/React/Zustand/Tauri 结构、多格式工厂或尚无真实消费者的抽象。

### R0：整理现有阅读切片（已完成）

只拆现有职责，不增加产品能力。Rust 入口只负责启动和组合；参数与窗口、受控协议、诊断与 benchmark 分别拥有实现。页面入口只组合内容加载、安全校验、分页和诊断。

退出条件：现有三样本、安全、固定几何、公式、翻页和 benchmark 全部保持通过；新功能不再需要继续堆入两个入口文件。

### R1：阅读会话与多章节输入（已完成）

用受控书根和最小 manifest 表示内容版本、有序 section、资源和可选 TOC。先使用现有解包 XHTML 样本，不实现 EPUB importer 或多格式抽象。阅读会话只暴露打开、关闭、内容已加载、布局已稳定和明确失败。

退出条件：多章节可以按顺序加载和释放；损坏 manifest、缺失资源与越界资源明确失败；单章节现有样本继续兼容。

### R2：Locator 与导航（已完成）

定义 point/range locator 的序列化、解析、比较与回落，完成 section 前后跳转、TOC 跳转和跨重排位置恢复。页码只是显示结果，不是耐久坐标。

退出条件：同一内容在翻页、字号和样式变化后恢复到原位置附近；无效 locator 安全回落并留下可诊断错误。

### R3：排版与阅读偏好（已完成）

在绝对设备像素页面契约上逐项加入字体、行距、固定边距、主题、书源样式和用户覆盖层。边距由阅读器保证，不向用户开放；这里只确定能力和状态所有权，具体控件与视觉另行设计。

退出条件：偏好变更不裁切内容、不破坏 locator，应用偏好与每书偏好职责清楚且可撤销。

### R4：内容交互（已完成）

依次处理键盘、鼠标和触摸翻页，文本选择与复制，书内与外部链接，脚注、图片、表格、代码和公式交互。一次 change 只实现其中一个可独立验收的纵向切片。

退出条件：交互不绕过资源与导航策略；新增控件具备键盘操作、焦点状态和读屏基本语义。

### R5：进度、恢复与书签（已完成）

分开会话热状态、每书耐久位置和用户偏好；合并高频进度写入并在关闭时 flush。书签作为 locator 的首个耐久消费者，用于验证版本变化后的恢复。

退出条件：正常关闭与异常恢复均不丢失最后稳定位置；书签可创建、跳转和删除；不因每次 relocate 写入全量状态。

### R6：书内搜索（已完成）

实现可取消的只读搜索，结果携带 locator 并可可靠跳转。只有真实大书证明主线程或重复计算成为瓶颈时，才增加 worker 或持久缓存。

退出条件：多章节结果完整、查询可替换或取消、错误不影响阅读会话，缓存即使删除也不丢失用户数据。

### R7：标注与引用（已完成）

第一版只完成选择、range locator、原文快照、高亮或笔记、软删除、保存和重画，并产生未来消息链路可消费的 `SourceAnchor`。不同时实现 notebook、同步或外部标注导入。

退出条件：标注事实与渲染 overlay 分离；重开和重排后可以恢复或明确报告重锚失败；保存失败不伪装成成功。

### R8：阅读器门槛（已完成）

用困难样本和大书复测安全失败、崩溃恢复、内存、冷开、热开、首个稳定页、翻页和重排，只优化测出的瓶颈。

退出条件：阅读器核心能力、事实所有者、module interface、真实目标证据和剩余风险均有独立 review；通过后才允许规划一种真实书籍来源。

## M3：一种真实书籍来源（已完成）

R8 通过后，只选择 EPUB3，将其转换为 R1 已稳定的内容输入。Windows host 通过 `--epub` 接受真实文件；导入 module 只拥有 ZIP、OPF、spine、navigation、资源边界和稳定内容身份，阅读语义继续由现有 WebView2 阅读器拥有。

实施与验收由 `docs/changes/epub-source-m3.md` 记录。不得因此继续建设多格式工厂、书架、云端来源、损坏书源修复或界面改版。

## M4：Atha 产品能力

书架、消息式阅读、Windows 正式壳、TTS、同步和其他产品能力不预先绑成一个大批次。每次只按真实阅读器 interface 和用户优先级交付一个可独立验收的产品切片，不为后续能力预建 schema、module 或占位界面。

### Tauri 与 Svelte 阅读应用壳（已完成）

首个产品化切片只把 Windows host 迁移到 Tauri 2，并用 Svelte 5 按职责拆分现有移动阅读壳；WebView2、单 WebView、受控书籍协议和无框架 reader kernel 保持不变。旧 Wry/Tao host 暂留作基线；后续功能由真实使用反馈决定，不预建书架、TTS 或同步骨架。

### 本地书架与应用内导入（已完成）

无启动参数时进入本地书架，通过 Tauri 官方文件对话框导入一个或多个 EPUB3。后端以内容哈希去重并用每书一份 JSON 保存受限书目，从 OPF 提取标题、作者和可选封面；打开书籍时切换既有受控书根，移除仅删除书架记录。首版不包含分组、排序设置、拖放、同步、多格式或后台导入队列。

### 完整消息式阅读（实现完成，验收中）

复用 R7 已稳定的选区、Locator 与 `SourceAnchor`，把现有标注和笔记迁移为同一 Message 事实的不同投影，不再长期维护 Annotation 双存储。正式后端使用 SQLite 保存 Conversation、Message、不可变修订、原文引用、历史渲染快照、消息关系与 Outbox；阅读页完成标注、笔记、回复、编辑、软删除、搜索、关系回顾、历史快照、跳回、重启恢复和自包含导出。完整范围和验收见 `docs/changes/complete-message-reading.md`；AI、同步与通用聊天继续暂缓。

初版只交付 Atha 自有的聊天界面和语义样式令牌。微信、Telegram、QQ 风格模拟、主题选择与用户自定义界面放在消息主循环验收之后，届时只替换展示主题，不复制消息数据或交互状态。

## 暂缓范围

- iOS、HarmonyOS 和其他移动平台；
- PDF、OCR、MOBI、AZW、词典、翻译、RSVP 与平行阅读；
- 云同步、账户、AI 书友和阅读统计；
- 商业化、遥测上传和生产发布。
