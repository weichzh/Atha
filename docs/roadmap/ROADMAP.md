# 路线图

路线图回答“为什么现在做这件事”。只有 `Now` 可直接进入调查；后续实施按 `docs/workflow/PROTOCOL.md` 分类和批准。`Next` 是按信号排序的候选，不是预先承诺的需求。

核心阅读、EPUB3、本地书架和消息式阅读已经形成完整主循环。当前阶段从“搭建架构与能力”切换为“验证真实日常使用并消除主循环阻塞”。架构风险是约束，不会自动成为产品待办。

## Now：日常阅读闭环验收

目标是在真实 Windows Tauri / WebView2 产品入口完成一次有边界的日常使用验收，并只选出一个最影响主循环的问题。

依次验证：

1. 无参数冷启动，从书架导入或重新打开三本代表性 EPUB；
2. 阅读、跨章导航、修改排版、关闭并恢复最后稳定位置；
3. 选择原文，创建标注或笔记，回复、搜索、跳回并重启恢复；
4. 导出当前书消息，并完成一次全库备份的可验证创建。

停止条件：

- 记录实际产品链路中的 P0 / P1 阻塞和重复摩擦，最多保留三个候选；
- 区分真实目标证据、本地检查与静态推断；
- 推荐一个最小纵向切片，写清用户结果、范围和验收；没有阻塞时明确结束，不为了维持开发而制造需求。

本轮是 `audit`，不顺手修复、不重构架构，也不把已知缺口全部转成待办。

## Next：由验收信号选择一个切片

候选按主循环影响排序；只有 `Now` 的证据命中时才创建 change：

1. **日常回流**：若用户难以找到并继续上次阅读，补齐最近阅读、继续阅读和明确的恢复状态；
2. **书源修复**：若真实书籍的 CSS 问题阻断阅读，完善每书用户 CSS 的发现、编辑、撤销与失败反馈；
3. **可安装交付**：若开发环境成为使用前提，建立可重复的 Windows 安装包与最小发布检查；
4. **针对性兼容或性能修复**：只处理固定样本可复现、现有正式门槛能验证的问题。

数据丢失、内容安全和引用错位始终高于体验优化。旧 host、bundle 顺序等工程风险只有在阻塞获批场景或其风险证据达到阈值时才进入 change。
