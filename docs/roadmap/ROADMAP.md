# 路线图

路线图只定义顺序，不授权生产代码修改。每个里程碑仍需独立规格、计划、交叉审阅和用户批准。

## M0：项目工作流初始化

目标：建立 `ACTIVE` 优先、规格先于代码、计划交叉审阅的项目记忆系统。

退出条件：

- 旧提案已迁移且不再与当前决策竞争；
- 架构、代码地图、数据库基线和路线图可独立读取；
- 文档守卫与长度检查通过；
- 工作流初始化形成独立提交。

## M1：Windows 后端工程初始化

目标：建立正式根 Cargo workspace 和最小后端 crate，但不实现产品功能。

必须先决定：

- crate 位置、workspace 成员和 P0 隔离边界；
- Rust 工具链、格式化、静态检查、测试和文档构建命令；
- M2 使用的固定 SQLite 方案、版本政策和迁移原则。

公开业务接口、错误模型和性能基准必须由首个真实用例驱动，在 M2 规格中决定，M1 不创建占位抽象。

退出条件：空后端可构建、检查命令可重复、没有业务占位代码。

## M2：HTML 阅读内核基础

目标：从书籍封装格式中抽离，先建立以 HTML、CSS 与本地资源为中心的高保真阅读内核，并用困难书籍样本验证浏览器级呈现与重内容性能方向。

必须先决定：

- 首个可实施切片的渲染技术边界和输入模型；
- 困难书籍样本的范围与浏览器对照方法；
- 书内脚本、外部资源确认和明确报错的安全行为；
- 缓存与渐进渲染的最小可验证行为。

退出条件由后续 accepted 规格定义。M2 不因本路线图而预先确定渲染技术、数据库 schema 或格式解包实现。

## M3：书籍导入与消息式阅读

目标：在阅读内核边界稳定后，将一种实际书籍来源送入内容模型，并完成书内引用消息、存档与回看的一条纵向链路。

退出条件：异常文件安全失败、资源上限、位置恢复、引用存档、消息关联和诊断脱敏均有验证。

## M4：Windows 前端壳

目标：在阅读内核和消息接口稳定后建立 Windows 窄窗口 UI，先接书架、阅读和消息浮层。

前端不得直接访问 SQLite。阅读、笔记和回顾状态按独立规格逐步加入。

## 暂缓范围

- iOS、HarmonyOS 和其他移动平台；
- PDF、OCR、MOBI、AZW 与词典；
- 云同步、账户和 AI 书友；
- 商业化、遥测上传和生产发布。
