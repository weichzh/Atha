# GitHub Issues：需求与验收交接

跨会话需求、研究、质量问题和真实环境验收使用 GitHub Issue；单次局部修复不用另建 Issue。已有 Issue 就复用。PR 用于审阅改动，不代替需求入口。

- **创建**：写目标、可观察的验收条件和必要边界。需要跨会话时，在最新交接说明中给出候选分支或 PR、提交、实际验证和未覆盖项，以及下一步与负责人。实现细节和检查明细链接到对应 change 或 PR，不在 Issue 复制。
- **恢复**：先读 Issue 正文及最近的有效交接，再核对分支、提交、工作区和证据。注明验证针对的是哪个候选。若没有可确认的候选或回执，明确写缺项和恢复动作。
- **关闭**：只有 PR 合入默认分支就能满足全部验收时，才用 `Closes` 等关闭关键字或 GitHub 会自动关闭 Issue 的关联方式。若还要做真机、真实书库、发布或其他验收，只在 PR 正文普通引用 Issue 编号，合并后留下下一步，验收满足后再关闭。
- **公开记录**：只发布可公开的摘要、脱敏数据或原创样本。私人书籍、笔记、原始日志和凭证不进入公开 Issue、PR 或提交。

用已配置的 GitHub 工具处理 Issues；CLI 可用 `gh issue view <编号> --comments` 查看。创建、编辑、评论和关闭 Issue 均按外部写入授权执行。
