# Atha 仓库协作与检查入口

开始、恢复或关闭仓库任务前读取 `AGENTS.md`、`CONTEXT.md`、`docs/ACTIVE.md` 和对应 Context Bundle。外部技术与标准的官方入口见 `docs/agents/references.md`；涉及框架行为、API、兼容性、错误或性能时，按需核对对应版本的官方文档或源码。

## GitHub Flow

1. **开短期分支**：新工作不在 `main` 上直接开发。独立任务以最新远端 `main` 为基线；确实依赖未合并工作时，记录所依赖的分支和提交。遇到正在使用或有未提交改动的工作区，用独立 worktree，不清理或搬动他人改动。
2. **提交并验证**：一个分支只处理一项相关变化，按影响范围跑现有检查。长期或需跨会话验收的工作关联 [Issue](issue-tracker.md)；小修不用先建 Issue。
3. **开 PR**：获准外发后，核对相对实际 PR 目标分支的差异和提交，确认没有带入无关改动、未获准公开的提交或私人材料，再推送任务分支并开 PR；需要早期反馈时可开 Draft PR。PR 写清范围、被测提交、环境、结果和未覆盖项。
4. **审查并合入**：PR 最终合入 `main`。处理阻塞意见和适用检查；候选或目标基线变化时，复核受影响的证据。获得明确授权后才合并。合并只表示改动进入 `main`；真实验收、发布和设备安装各自确认。
5. **收尾**：合并后更新相应 Issue；仍待验收的 Issue 保持打开。确认无后续分支依赖且获准清理后，删除短期分支。不为切换流程而重写已有 `main` 历史或迁移在途工作。

## 工作路径

- `audit`：有明确对象和停止条件的只读调查，不自动升级为实施；
- `fast`：局部、可回滚且不改变依赖、接口、数据、安全或信任边界的维护，更新受影响事实所有者；
- `change`：产品行为、依赖、架构、数据、验收或跨模块变化，实施前需有已批准且状态为 `accepted` 的 `docs/changes/*.md`，完成后做独立 review。

一份 change 同时记录问题、范围、验收、文件与步骤、检查、结果、review 和剩余风险。除非具体工作确有必要，不机械新建 milestone、spec、plan 和 review 副本。首次编辑时保留所有无关的用户改动，只处理本任务授权的范围。

## Review、迭代与证据

独立 review 只读检查实现与验收条件，并把发现分为 `blocking`、`non-blocking`、`out-of-scope`。迭代任务在同一份 change 中按 Review、Repair、Validate 记录轮次、剩余差异、停止原因与证据等级；完整命令和输出按需保存在 Git 忽略的 `artifacts/local/`，不把计划命令、静态阅读或截图说成未执行的检查通过。

检查从成本最低且最能区分假设的步骤开始：配置、语法和静态预检，受影响 Module 的目标检查，仓库 gate，最后才是高成本 GUI、真实目标或 benchmark。低成本检查失败时先停止扩展并修复；预期拒绝必须由项目脚本确认正确失败类型并返回零，意外接受、错误失败类型或未完成检查返回非零。

## 仓库检查

- `bash scripts/check-docs.sh`：文档守卫与长度检查；
- `bash scripts/check-workflow.sh`：仓库流程文档与脚本自检；
- `bash scripts/check-fast.sh`：本地快速检查集合；
- `bash scripts/check-reader-linux.sh`、`bash scripts/check-pct-reader.sh` 和各领域脚本：按任务与目标选择，不以本地结果代替真实设备或生产验收。

项目脚本是检查入口。Issue 保存跨会话交接，change 保存获批范围、技术决策和验收证据，PR 保存候选差异与审查，`ACTIVE` 只保留当前入口；不在四处重复记录进度。本机临时收据只保存在忽略目录。关闭任务前更新事实所有者与 `ACTIVE` 指针，运行相称检查，并明确列出未运行或未覆盖项。旧 PowerShell 脚本只在仓库明确记录为兼容入口时使用；Rust 版本由 `rust-toolchain.toml` 固定。
