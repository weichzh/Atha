# 微信读书式移动阅读壳层

## Status

implemented

## Problem

现有阅读器把全部功能长期堆在桌面工具条中，既不像成熟移动阅读产品，也会让控制层与正文争夺空间。已选定的视觉方向是贴近微信读书移动端：默认沉浸阅读，点击正文中央后才显示临时控制层，局部功能只展开一个面板。

## Scope

- 将固定阅读页调整为 `780 × 1680` 设备像素的竖屏比例，继续隔离系统 DPI；
- 默认隐藏控制层，点击正文中央切换显示，左右区域继续翻页；
- 顶部左侧提供返回，右侧提供当前位置书签和更多菜单；更多菜单容纳亮度、主题、字号、字体、密度和本书样式；
- 底部只显示目录、搜索、笔记、进度、听书五个图标，听书本次只占位；
- 目录面板只使用一个列表，已有书签作为对应章节下的目录项；书签添加或取消只通过右上角书签图标；
- 搜索、标注、书签、偏好、翻页和进度继续复用现有模块与持久化；
- 控制层覆盖正文边缘，不改变阅读页尺寸、分页或正文位置。

## Non-Goals

- 不实现听书；
- 不实现桌面或横屏专用布局；
- 不改变 EPUB、Locator、搜索、标注和持久化的数据语义；
- 不在本轮重新设计引用消息流程。

## Acceptance Criteria

- [x] 初次打开只有竖屏书页、章节内容和右下角进度，没有常驻工具条；
- [x] 点击正文中央显示或隐藏控制层，显示前后阅读页矩形与当前位置不变；
- [x] 顶部没有搜索入口，左侧返回、右侧书签可操作，更多菜单内的亮度与字体设置可操作；
- [x] 底部依次只有目录、搜索、笔记、进度、听书五个无文字图标；
- [x] 目录面板没有搜索或书签编辑控件，书签位于对应章节下，章节和书签均可直接跳转；
- [x] 搜索、笔记、进度面板互斥，听书明确为尚未实现；
- [x] 移动竖屏明暗主题无横向溢出、文本遮挡或控制层导致的正文重排；
- [x] 新增壳层检查和目录书签持久化检查通过；既有正式检查的未决项见证据。
