# 继续阅读和书架布局

## Status

implemented

## Problem

「继续阅读」和藏书共用滚动区。读者既想立即回到当前书，又希望先看到书架；移动端的封面列数和桌面的密度也需要可调。

## Scope

从已获准分批交付的移动书架改动中提取继续阅读、设备布局偏好和封面信息。保留最近书籍、完整筛选、布局切换、批量整理和开书/返回契约。先基于 #13 的书架界面整合，等其合入后以最新 `main` 验证。本批不改设置页整体架构、阅读控件或系统栏。

## Architecture Impact

none

继续阅读沿用书架最近阅读投影和开书入口。列数、密度等仅是设备 UI 偏好；不修改书籍或阅读记录的备份格式。

## Acceptance Criteria

- [x] 继续阅读条可打开上次在读项，也可收起；收起后仍能展开最近书籍并恢复阅读条。
- [x] 搜索/筛选时收起阅读条，多选时让出底部操作区；移动端避免遮挡主导航或最后一行书籍。
- [x] 2 / 3 / 4 列、桌面密度、封面书名与作者偏好可配置，重载保持；保留原有网格和清单。
- [x] Esc 与原生返回先关最近书籍；打开其中一本再返回时，恢复书架位置及相关焦点。

## Files And Steps

继续阅读组件与设备偏好接入现有书架和应用设置；定向覆盖入口、布局、自定义偏好及开书往返。[Issue #1](https://github.com/weichzh/Atha/issues/1) 跟踪真实链路。

## Checks

Svelte、Vite、工作流及桌面和 390px Chromium 实际交互。

## Iteration Control

- Mode: `iterative`
- Maximum repair iterations: `2`
- Unchanged-delta limit: `1`
- Human stop: 需要写入设备或改变书籍数据边界时停止。

## Result

继续阅读移至固定阅读条，窄屏在主导航上方，最近书籍使用原生对话框。收起状态及布局偏好保存在此设备；搜索和筛选只临时收起，多选不显示。去掉书架标题下重复的册数。

首轮端到端在设置导航定位失败：fixture 用按钮角色查找了已声明为 tab 的控件。修正后窄屏专项和完整 Chromium 回归均通过；验证三种列数、重载保持、收起与恢复、Esc、原生返回、书架往返与焦点。复看阅读条和抽屉，限制长书名为两行，等封面实际加载后取证。Svelte 检查、Vite 构建和工作流检查通过，未发现阻塞，停止本地迭代。

## Review

公开候选基于已合并的 #13，不含设置页整体重做、原生系统栏和阅读控件。等待独立 PR 审查。

## Evidence And Residual Risks

窄屏和桌面 Chromium 使用隔离原创书库，Android 返回由现有桥接入口模拟；未运行 Android、Windows 或真实书库。
