# 阅读记忆返回后刷新

## Status

implemented

## Problem

同文档打开书籍时，阅读记忆保留了查询与列表，但返回后不会刷新；刚写的回复需重新输入查询才出现。连续搜索时，先发后到的旧响应也可能替换新结果。

## Scope

从已批准交付的阅读交互 V2 中独立拆出阅读记忆刷新与请求排序。保留当前查询、跳回原文入口及历史快照；不改 Messages、Locator、书架界面或 IPC 契约。

## Architecture Impact

none

## Acceptance Criteria

- [x] 返回阅读记忆时按原查询重新读取书架与消息，新回复不用再次搜索就能出现。
- [x] 新查询、离开页面和返回都让旧响应失去更新权限。读取失败提供重试，不显示为零结果。
- [x] 同文档与原生历史恢复沿用既有入口，源书与快照仍按原边界读取。
- [ ] 独立审查后合入。

## Files And Steps

应用壳告知阅读记忆是否可用；阅读记忆在重新进入和历史恢复后刷新，给每个查询分配版本。

## Checks

Chromium 验证同文档往返实际保存回复、IPC 乱序和失败重试；Svelte、Vite 与工作流检查。

## Iteration Control

- Mode: `single-pass`

## Result

Chromium 以「快照」为查询，从命中跳回原书、实际保存新回复、返回后在原查询下看到新回复。模拟 IPC 先回新搜索再回旧搜索，仍显示新结果；拒绝响应后重试恢复。模拟历史恢复事件仍按原词重新查询。Svelte、Vite 和工作流检查通过。

## Review

用同一个请求版本管理输入、返回和离开；同词刷新保留已显示的列表，不闪回加载页；新词只展示该词的结果。待独立审查。

## Evidence And Residual Risks

浏览器与 IPC 模拟证据不替代 Android 实机、Windows 或完整真实书库验收。
