# 阅读工作区回跳与长回复

## Status

implemented

## Problem

Linux WebKitGTK 中，约 1000 CSS px 的窗口从阅读记忆跳转到非首屏的唯一引文后，关闭对话会显示本节末页；会话引用正确，正文却不在原处。同一宽度下，约 1600 字的单段回复还会把对话栏和发送按钮撑出屏幕。两项都用原创 EPUB 与隔离资料目录复现。

## Scope

用户批准同时修这两项。保留现有窄屏、B+C 和 A+B+C 布局、消息富文本、源锚点契约和操作位置；不重新设计对话，不改书籍数据或权限。

## Architecture Impact

present

涉及阅读界面显示与共享导航重排的衔接；优先保留负责当前书／章节的有效正文位置，让现有导航在正文可测量时恢复，而不是在每次关闭面板时无条件重跳历史引文。对话溢出由现有组件布局消化，不改消息内容、编辑器协议或视口断点。

## Acceptance Criteria

- 360、约 1000 和 ≥1440 CSS px 从阅读记忆恢复会话，展开可见正文后，原文唯一高亮在实际阅读页内。同节另一页不能冒充恢复成功；不能因历史引文覆盖用户后来主动翻页或跳章。
- 约 1000 CSS px 的同类单段长回复不会撑宽对话，内容能在栏内换行或按原语义局部滚动，发送按钮可见、可继续输入并提交。多段、普通回复和既有窄／宽屏布局不退化。
- 先在真实复现证据与测试中对照失败，再以集成候选的目标 WebView 确认。完整 AppImage 验收使用对应产品包。

## Files And Steps

按阅读位置和对话几何拆分修改；合并后用同一原创 EPUB 检查真实选区、回复、返回、恢复可见原文和继续发送。

## Checks

受影响的导航与浏览器回归、仓库本地提审门、GNOME Wayland／WebKitGTK 完整功能门及 AppImage 包的实际启动和验收。

## Iteration Control

- Mode: `iterative`
- Maximum repair iterations: `4`
- Unchanged-delta limit: `1`
- Human stop: 当前显示不可用时保留本地结果并等待重连；不读取真实书库、不安装或发布。

## Result

修复前 360 CSS px 能在第 11/22 页看到高亮；1000 CSS px 关闭面板后显示第 13/13 页，原文 Range 的左边界约 −4690 CSS px，正文页可视范围为 120–880 CSS px。另有约 1600 字单段将对话宽度撑到约 27,214 CSS px 的截图与日志。

原生验收保留唯一正文 Range 与同章错页对照，再以实际 Markdown 控件发送一个长单段，核对对话栏、段落和发送控件在屏幕内，随后实际发送短回复。

- 回跳：旧版在正文隐藏时曾按 1px 排版并把页数压缩为 1/1。修复后隐藏正文退出分栏但保留分页几何，重排只在有效尺寸下执行；保留本次跳转的精确落点，后续翻页、切章或用户滚动清除该位置。Chromium 的 360、1000→1010 和 1500 CSS px 实测唯一引文在页内；独立导航与进度单测通过。
- 长回复：限制工作区的行内尺寸，保留消息内换行和局部滚动。Chromium 在 1000×713 CSS px 实测 C 栏约 650px，全文可达，发送下一条成功；360 和 1440 CSS px 正常对话通过。两项在本地合并候选 `cddff83` 一同进入最终 AppImage 验收。

## Review

- 独立审查发现：用户主动翻页后，A+B 和 B+C 的连续重排仍可能用窄栏的新页首覆盖原来位置。保留首次重排选中的有效位置直至下一次主动导航，浏览器回归先等待 A+B 真实重排后才打开对话。
- 配套验收补齐 DOMRect 测试夹具和所有原生输入的超时直接停止；原文高亮后的工具栏改用已有 `h` 快捷键，避免实际中心点击命中高亮、打开选区操作而误判工具栏未响应。
- 在 `695f26b`，本地快速门和完整 Chromium 套件通过。定向反例确认旧逻辑把重排前偏移 50 变成 40，修复后恢复 50；13 项原生预检覆盖指针、动作键、文字输入及点击超时。
- 同一 `695f26b` 的实际 Linux AppImage 完整验收通过。在 360、1000、1600 CSS px，关闭对话后唯一高亮都位于正文内；切到同章另一页能拒绝相同对话引用。1000 CSS px 实际发送约 1600 字单段，内容完整换行，发送按钮保留并成功再发短回复。原生截图和 JSON 见本机 `linux/final-appimage.Q46ch101/`。
